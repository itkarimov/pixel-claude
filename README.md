# Pixel Claude

Голосовая пиксельная оболочка над `claude` CLI. Вертикальное окно: сверху 60 % —
портрет персонажа с эмоциями, снизу 40 % — лента сессии (что сказали, что делаю,
что ответила). Говоришь в микрофон — она слышит, работает и отвечает голосом.

## Запуск

Ярлык **Pixel Claude** на рабочем столе. Или:

```bash
python app.py
```

Крестик не закрывает окно, а прячет его в трей — процесс `claude` продолжает
держать сессию, микрофон работает. Клик по значку в трее возвращает окно, там же
в меню правой кнопкой — включение микрофона и настоящий выход.

## Как это работает

```
микрофон → энергетический VAD → faster-whisper (ru, локально)
        → claude -p --input-format stream-json --resume <session>  (+ кадр с камеры)
        → лента + эмоция портрета + piper (локально) → динамики
```

- Один долгоживущий процесс `claude` на всю сессию, реплики уходят ему в stdin.
  Контекст держится через `--resume <session_id>`. Проверено: `--resume` не
  плодит новые id — один файл живёт весь разговор.
- В системный промпт дописано требование отвечать одной-двумя фразами и ставить
  тег эмоции: `[done] Готово, поправила три файла.` Тег снимается перед показом
  и озвучкой, портрет переключается на нужный спрайт.
- Пока играет голос, микрофон заглушён — иначе оболочка слышит саму себя.

## Скорость

Мерить надо на своей машине: всё ниже снято на ноутбучном Ryzen 7 3700U
(4 ядра, без CUDA, 7 ГБ ОЗУ), на другом железе расклад будет другой.
Инструменты замера лежат в `tools/`, числа воспроизводимы.

Путь от «человек замолчал» до «пошёл звук» — четыре стадии, и тормозила каждая:

| стадия | было | стало | чем |
|--------|------|-------|-----|
| пауза после фразы | 0.90 с | 0.55 с | `vad_silence_ms` |
| распознавание | 5.64 с | 1.62 с | whisper `small` → `base` |
| ход модели | 5.90 с | 2.20 с | `--setting-sources project,local` |
| синтез речи | 1.86 с | 0.32 с | piper вместо edge-tts |
| **итого** | **≈14 с** | **≈5.5 с** | |

### Распознавание: `small` работал вхолостую

`tools/bench_latency.py stt`, одна и та же фраза длиной 5.6 с:

```
tiny    0.75 с   RTF 0.13
base    1.61 с   RTF 0.29
small   5.64 с   RTF 1.00   ← стояло раньше
```

`small` выдавал ровно тот же текст, что и `base`, и тратил на это лишние четыре
секунды. RTF 1.00 означает буквально: сколько человек говорил, столько же он
потом ждёт.

### Ход модели: хуки срабатывают на каждую реплику

Долгоживущий процесс убрал инициализацию, но ход всё равно занимал 5.9 с. Вина
не модели: хук `UserPromptSubmit` плагина claude-mem запускает node на **каждое**
сообщение и стоит 1.5–2.5 с, а вместе с `Stop` и `PostToolUse` — 3.7 с на ход.
Долгоживущий процесс тут не помогает: хук на то и хук, чтобы срабатывать каждый
раз.

`tools/bench_modes.py`, прогретый процесс, время до первой фразы:

```
как есть                          5.90 с   старт 9.24 с
--setting-sources project,local   2.19 с   старт 2.46 с   ← выбрано
--safe-mode                       2.15 с   старт 2.33 с
```

Взят первый вариант: он снимает пользовательские настройки (в них хуки), но
оставляет `CLAUDE.md` и правила проекта — оболочка работает внутри проекта, они
ей нужны. Переключается ключом `hooks_mode`.

**Ловушка:** флаг `--bare` в справке выглядит идеально («skip hooks») и в замере
даёт 0.05 с на ход. Это не ускорение — он не читает OAuth и отвечает «Not logged
in · Please run /login». Замер, который не проверяет `is_error`, покажет
стократный прирост на пустом месте. Проверка: `tools/bare_check.py`.

### Синтез: сеть съедала больше, чем сам синтез

```
edge-tts целиком в файл, потом ffmpeg   1.86 с   ← как было
edge-tts потоком, соединение свежее     0.62 с
edge-tts потоком после паузы            1.70 с   ← так и живёт на практике
piper локально                          0.30 с   ← выбрано
```

Две находки. Первая: ffmpeg по умолчанию разведывает формат входа и придерживает
звук лишние 0.23 с — лечится `-probesize 32 -analyzeduration 0`, формат мы и так
знаем. Вторая, главная: каждая фраза edge-tts открывает новое соединение с
сервисом Microsoft, и рукопожатие TLS стоит около секунды. Подряд идущие фразы
укладываются в 0.6 с за счёт переиспользования сессии, но пауза между репликами
всё обнуляет — а у голосового помощника паузы это норма жизни.

Поэтому синтез локальный: piper, голос `ru_RU-irina-medium`, 0.30 с до звука,
скорость синтеза ×9 от реального времени. Плюсом — работает без интернета и не
отправляет текст ответа наружу. Голос edge-tts живее; кому важнее он, ставит
`"voice_engine": "edge"` и платит те самые 1.4 с. Послушать и сравнить:
`python tools/piper_probe.py --play`.

### Что ещё сделано

- **Процесс и голос греются при старте окна**, пока человек тянется к микрофону.
  Для piper это критично: загрузка модели 4.6 с плюс первая фраза 5.3 с, на ней
  onnxruntime раскладывает граф. Дальше 0.3 с.
- **Озвучка законченными предложениями** по мере их прихода
  (`--include-partial-messages`), не дожидаясь конца ответа.
- **Сначала фраза, потом работа.** Если задача требует инструментов, промпт
  требует сперва сказать «сейчас посмотрю» и только потом браться за дело —
  иначе человек сидит в тишине по десять секунд и думает, что всё зависло.
- Реплика, сказанная до конца хода, не отбрасывается, а придерживается в очереди.

### Сервер не нужен

Мысль «вынести на VPS» напрашивается, но не работает: сама модель и так считает
на серверах Anthropic, ближе её не подвинешь. Распознавание и синтез после
правок считаются локально за 1.6 с и 0.3 с — отправлять звук на чужую машину
значит добавить сетевой путь к тому, что уже быстро. Единственное, что дал бы
GPU-сервер, — примерно секунда на распознавании, ценой денег, задержки сети и
ухода голоса наружу. Время уходило не туда, где его искали.

## Камера

Кнопка **ГЛАЗА** рядом с микрофоном. Пока зрение включено, в углу портрета идёт
живой предпросмотр крупными пикселями, а на самой камере горит лампочка — видно,
что она смотрит.

Кадр уходит блоком `image/base64` прямо в потоке stream-json. Через файл на
диске тоже работает, но модель тратит лишний ход на чтение: 8.7 с против 7.0 с
(`tools/vision_probe.py`).

Дальше два приёма, чтобы зрение не стоило дорого:

- **Один и тот же кадр не отправляется дважды.** Сцена сравнивается по серому
  отпечатку 32×32, приведённому к нулевому среднему — иначе камера сама себя
  «меняет», плавно подстраивая экспозицию. Порог 0.6 подобран замером
  (`tools/vision_dedup_probe.py`): покой за 8 секунд уходит максимум на 0.48,
  закрытая десятая часть кадра даёт 0.76.
- **В спокойные минуты вместо кадра идёт фраза.** Фоновый описатель
  (`core/watcher.py`) раз в полминуты, и только если картинка поменялась,
  спрашивает у haiku «что видно» и держит ответ наготове. В реплику подмешивается
  строка `[вижу] …` — несколько десятков токенов вместо четырёхсот за кадр.
  Что она видит, пишется в ленту: камера не должна быть чёрным ящиком.

Процесс описателя живёт, но раз в `watch_recycle_every` описаний поднимается
заново: в долгоживущем каждый кадр оседает в контексте и стоит ~590 токенов в
каждом следующем ходе (`tools/bench_describer.py`).

На прямую просьбу — «посмотри», «что видишь», «что у меня в руках» — кадр всегда
берётся свежий, даже если сцена «та же». Описание минутной давности на такой
вопрос было бы враньём.

Камера выключена по умолчанию и включается только руками.

### Установка камеры и голоса

```bash
pip install opencv-python-headless piper-tts
python -m piper.download_voices ru_RU-irina-medium --download-dir assets/voices
```

Встроенные камеры ноутбуков капризны: `ov9734` и родня не видны через Media
Foundation и открываются только старым DirectShow, причём неудачная попытка не
падает с ошибкой, а молча висит. Какой способ работает на вашей машине —
покажет `python tools/camera_probe.py`, ответ кладётся в `camera_backend`.

## Сессии

Выпадающий список над лентой — **тот же, что в сайдбаре приложения Claude**, с
теми же названиями: «Крипта», «Instagram carousel», «БОТ персональный ДДС».
Сессии всех проектов сразу, свежие сверху, рядом с названием — папка проекта.
Выбрали — оболочка продолжает эту сессию (`--resume`), **переключает рабочую
папку** на её `cwd` и подтягивает в ленту последние реплики, чтобы не начинать с
пустого экрана. Кнопка `+` начинает новую в папке из `config.json`.

Последняя сессия запоминается в `state.json` рядом с `config.json`, поэтому при
следующем запуске окно продолжает с того же места. Файл локальный, в гите его нет.

### Откуда берутся названия

Приложение держит свой реестр сессий в IndexedDB (`%APPDATA%\Claude`), и лезть
туда из питона было бы больно. Но заголовок, заданный в приложении, оно
дублирует записью `custom-title` прямо в файл CLI-сессии — оттуда и читаем,
с конца файла, наращивая окно поиска.

```
~/.claude/projects/<путь проекта с дефисами>/<session_id>.jsonl
```

Путь кодируется заменой **любого** не-буквенно-цифрового символа на дефис,
включая точки и подчёркивания:
`C:\Projects\my_app` → `C--Projects-my-app`.

Безымянные сессии (прогоны CLI, фоновые агенты claude-mem) в приложении не
показываются — в списке их тоже нет. Если нужны, есть
`sessions.list_sessions(unnamed=True)`.

### Сессии, заведённые здесь, в приложении не появятся

Приложение ведёт сайдбар по своей базе с собственными идентификаторами вида
`local_af3ad0db-…` — среди 589 файлов CLI-сессий таких нет вовсе. То есть у него
свой реестр, а в файлы сессий оно только проставляет заголовок. Зарегистрировать
там сессию снаружи нечем, и лезть в чужую IndexedDB — плохая идея.

Поэтому оболочка ведёт свой реестр `mine.json`: сессия, начатая здесь,
запоминается с заголовком по первой фразе и показывается в списке с меткой `▸`.
В приложении Claude она не появится — это ограничение, а не поломка.

## Переспрашивание

Оболочка работает в настоящем проекте с `permission_mode: acceptEdits` —
сказанное вслух доходит до файлов без единого клика. А между человеком и файлами
стоит распознавание речи, которое иногда слышит своё.

Поэтому просьбы, меняющие мир необратимо или наружу — удалить, перезаписать,
закоммитить, запушить, задеплоить, отправить, установить, откатить — не уходят
сразу. Помощница повторяет услышанное вслух: «Поняла так: … Выполнять?» — и ждёт
«да». Безобидные просьбы идут как шли, иначе подтверждение из страховки
превращается в тик.

Ответить можно голосом или кнопками **ДА** / **НЕТ** в полосе под лентой:
если распознавание уже один раз ослышалось, повторять «нет» в микрофон — так
себе способ отменить. Если сказать что-то третье, это считается новой
формулировкой — прежняя просьба снимается. Молчание дольше
`confirm_timeout_sec` — отказ, о котором вслух не объявляют: голос из угла,
вспоминающий про забытую полминуты назад просьбу, пугает сильнее, чем молча
несделанное дело.

По умолчанию переспрашивание только для голоса (`confirm_mode: voice`):
набранный руками текст человек видел глазами.

## Приватность

Приложение **не открывает никаких портов** — ни сервера, ни сокетов, входящих
соединений не принимает.

С настройками по умолчанию **наружу не уходит ни звук, ни текст ответа**:
распознаёт локальная faster-whisper, синтезирует локальный piper. Наружу идут
только сами реплики — в Anthropic, как и в обычном claude CLI.

Что меняет это равновесие:

- `"voice_engine": "edge"` — текст ответа поедет в сервис синтеза Microsoft;
- включённая камера — кадры уходят в Anthropic вместе с репликой, а при
  `watch_enabled` ещё и фоновому описателю. Камера выключена по умолчанию, и
  пока она включена, на ней горит лампочка.

`config.json`, `state.json`, `mine.json`, `crash.log`, `bench_tmp/` и
`assets/voices/` в гит не попадают. Свой `config.json` создаётся из
`config.example.json` при первом запуске.

## Настройки — `config.json`

| Ключ | Смысл |
|------|-------|
| `workdir` | в какой папке работает claude |
| `model` | пусто = модель по умолчанию |
| `permission_mode` | `acceptEdits` — правки файлов без вопросов, Bash по-прежнему спросит и в headless будет отклонён. `bypassPermissions` снимет все тормоза — на свой риск |
| `hooks_mode` | `skip_user` — без пользовательских настроек и их хуков (−3.7 с на ход), `safe` — вообще без надстроек, `keep` — как обычно |
| `stream_partial` | отдавать текст по кускам и говорить с первой готовой фразы |
| `voice_engine` | `piper` локально (0.3 с), `edge` через сеть (1.7 с, но голос живее), `system` — SAPI |
| `whisper_model` | `tiny` / `base` / `small` — на слабой машине `tiny`, `small` брать незачем |
| `vad_start_rms` | порог громкости начала фразы; шумный микрофон — поднять |
| `vad_silence_ms` | сколько молчать, чтобы фраза считалась законченной |
| `camera_backend` | `DSHOW` или `MSMF` — что сработало в `tools/camera_probe.py` |
| `camera_change_threshold` | насколько должна измениться картинка, чтобы слать её снова; `0` — слать всегда |
| `watch_enabled` | фоновый описатель камеры |
| `confirm_mode` | `voice` / `all` / `off` — когда переспрашивать перед необратимым |
| `portrait_share` | доля высоты под портрет |

## Эмоции

`neutral` `smile` `happy` `laugh` `surprised` `puzzled` `think` `sad` `crying`
`angry` `unhappy` `shy` `love` `tired` `sly` `excited` `relief` `victory` `done`

Портрет нарезан из листа `assets/ref.png` (40 клеток, 8×5). Клетки режутся не по
формальной сетке — она на листе неровная, — а по двум привязкам: центр фигуры по
массе тёмного и верхняя линия волос. Поэтому голова стоит на месте при любой
смене эмоции. Арт на листе нарисован с двукратным апскейлом, спрайты приводятся
к родному разрешению 88×98 — так целочисленное масштабирование окна даёт частый
шаг и портрет заполняет панель.

Все 40 клеток лежат в `assets/sheet/r<ряд>c<колонка>.png`, общий вид —
`assets/preview_grid.png`. Чтобы поменять, какая клетка отвечает за эмоцию,
правьте `MAPPING` в `tools/slice_ref.py` и перенарежьте:

```bash
python tools/slice_ref.py
```

Список эмоций задаётся в `core/agent.py` (`EMOTIONS`) — оттуда он попадает в
промпт. Добавляете спрайт — добавьте имя туда же, иначе тег не распознается.

Моргания нет: на листе нет кадра с закрытыми глазами и нейтральным ртом, а
подставлять чужую позу — заметно. Вместо него портрет чуть покачивается,
имитируя дыхание.

## Если что-то не работает

- **`claude CLI не найден`** — проверь, что `claude` есть в PATH.
- **`401 OAuth access token has expired`** — вылетела авторизация CLI. Открой
  терминал, запусти `claude` и войди заново.
- **Микрофон не слышит** — подними `vad_start_rms`, проверь устройство ввода
  по умолчанию через `python tools/audio_test.py`.
- **Молчит** — `python tools/audio_test.py --play`; если edge-tts не отвечает,
  включится системный голос Windows.
